# 安全作业承载力分析

`<技能>` = 本文件所在目录的绝对路径。

## 第 0 步：人工确认（强制，不得跳过）

用户说「出报告 / 生成日周月」时，**先确认再跑命令**。缺确认直接 `runReports` 视为违规。

1. **数据来源**：用户上传了 `.xls/.xlsx` → 用上传文件；否则用 `<技能>/data/工作计划-测试数据.xls`。向用户说清本次数据源。
2. **锚定日**：用户给了日期就用；没给默认 `2026-09-01`（或用户说「今天」则用当天）。
3. **先算再建建议**：按下方「辅助建议六维」写【AI 辅助建议】草稿，必须带具体单位与百分比，禁止空话。
4. **向用户展示并等待确认**（用下面「确认展示模板」）：
   - 本次要出的每一份报告的建议正文（只出日报只展示「报告-日」；`--all` 则日/周/月三键）
   - 所属机构（默认 `国网青岛供电公司安全生产委员会办公室`，用户可改）
5. 用户确认 / 修改后，把建议写入 JSON（结构见「建议 JSON 模板」），再执行下方命令；`--office` 传确认后的机构名。

代码层：报告缺 `--advice` 或缺 `--office` 会直接 USAGE 失败。建议章正文由 `_advice_from_numbers` 按六维模板生成，不抄 JSON 散文；`--advice` 用于证明已确认并满足 CLI 校验。

## 辅助建议六维（强制·上会口径）

「三、辅助建议与风险管控提示」是给领导的**短管控意见**，不是概况复述。六维标签名固定，顺序固定，一段连写（不加换行标题）。无数据的维可一句带过，**不得**整章写成「请各单位按实际安排」。

### 六维对照表

| 序号 | 标签 | 一句话职责 | 必须写出的内容 | 禁止写法 |
|---|---|---|---|---|
| ① | 【判断】 | 负荷态势 | 总体轻载/适中/偏重/偏紧；满载(≥90%)与重载(75%~90%)单位名单+百分比；主矛盾单位 | 只写「居前三名」、不分级 |
| ② | 【风险】 | 高风险叠加 | 三/四/五级项数；满载/重载单位是否同期有三级（或点名叠加） | 只报个数、不点名叠加 |
| ③ | 【管理】 | 人员与管理 | 全网管理承载力%；满载/重载时说明检查频次或到岗到位 | 只甩一个全网%就结束 |
| ④ | 【措施】 | 计划统筹 | 对满载、重载分别给可执行动作；编号用 `1．` `2．` `3．` | 「请压缩」「请统筹」无对象 |
| ⑤ | 【反馈】 | 责任时限 | 谁落实、何时反馈（默认：满载/重载单位安监会同生产部门，下一工作日前） | 无主责、无时限 |
| ⑥ | 【底线】 | 例外底线 | 保电、紧急消缺、重大风险不得一刀切取消 | 一律「压减」不设例外 |

### 填空主模板（生成器按此拼接）

把 `{…}` 换成本次计算结果；无满载/重载时写「无」，不要删整句。

```text
【判断】{当日/本周/本月}作业承载力总体{轻载/适中/偏重/偏紧}。满载单位：{单位A}{xx.x}%、{单位B}{xx.x}%；重载单位：{单位C}{xx.x}%、…（没有则写「无」）。矛盾主要集中在{主矛盾单位或「各单位」}。
【风险】本周期三级{n}项、四级{n}项、五级{n}项。其中{满载或重载单位}三级{n}项，与满载/重载区间重叠，存在「高负荷+高风险」叠加，须重点盯防。（无叠加时改为：满载/重载单位须严控与三级风险作业的时段叠加。／本期未出现满载/重载与三级风险的显著叠加。）
【管理】全网管理承载力{xx}%，{总体可支撑，但满载/重载单位检查频次应高于常规／管理侧已偏紧，到岗到位不得放松／现场管理人员总体满足管控需求}。
【措施】1．对{满载单位}：立即组织计划清理，非紧急四级/五级作业错峰或暂缓，满载解除前原则上不新增长周期作业；2．对{重载单位}：控制新增计划，优先保障已批复三级及紧急消缺；3．其他单位按预警分级动态管控。（无满载/重载时只保留「各单位按预警分级动态管控…」一条。）
【反馈】请{满载/重载单位}安监会同生产部门于下一工作日前反馈计划调整结果。
【底线】涉及保电、紧急消缺、重大风险管控的作业，须履行审批后实施，不得简单取消。
```

## 立刻执行（确认完成后）

```bash
python "<技能>/scripts/runReports.py" \
  --source "<技能>/data/工作计划-测试数据.xls" \
  --all \
  --report-date YYYY-MM-DD \
  --advice "<技能>/承载力报告/建议/advice_YYYYMMDD.json" \
  --office "国网青岛供电公司安全生产委员会办公室" \
  --out-dir "<技能>/承载力报告" \
  --chart native
```

用户上传了计划文件时，只把 `--source` 换成该文件绝对路径。

成品在 `<技能>/承载力报告/承载力报告{当天YYYYMMDD}/`：

- `国网青岛供电公司2026年M月D日安全承载力分析报告.docx`
- `国网青岛供电公司2026年M月份第N周安全承载力分析报告.docx`
- `国网青岛供电公司2026年M月份安全承载力分析报告.docx`

只出一份时把 `--all` 换成 `--template 报告-日|周|月`。

## 版式（代码已固化，不要手改成品）

- 报告里独立成段的「注：…」会删掉。不删正常数据。
- 表不拆「续表」。**工作计划概况明细表（序号表，含月报）不两字挤压**，按列语义偏好宽排；**周报日承载力矩阵等宽表**才两字挤压+软换行（代替续表）。表单元格细黑边框齐全。
- 概况句写清三级/四级/五级项数；明细表只列三/四/五级中**数量最少**的一档，标题动态为「X级风险工作明细表如下」。
- 图是 Word 可编辑的 DrawingML（`c:chart`）。分类轴标签**完整原文、一字一行**，禁止截断；`tickLblSkip=1` 全显示。分类轴和数值轴 `crosses=min`。纵轴**不写「项/%」轴标题**（百分图刻度自带 `%`）。
- 月报图1（作业类型数量）与承载力图同一套竖柱规范；月报每一周单独一页。

## 不要改的计算口径

- θ：工作内容或作业类型去空白后正好是「装表接电」时取 0.2。
- β：配置「强制统一β」在 `parse_person` 读取。当前 true，每人用默认 1.0；false 时用人员档案「作业素养能力」。
- 班组公式按人员档案「班组类型」。多班组名称写成「班组名-人数」。
- 「电网风险等级」不参与计算。风险只用「作业风险等级」。
- 周报标题日期不带全角括号。月报各周标题仍保留括号。
- 建议章只来自 `genReportParams._advice_from_numbers`（六维模板）。
- 预警只有轻载 / 适度 / 重载 / 满载。超过 100% 仍是满载。没有停工档。

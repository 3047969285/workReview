# 安全作业承载力分析

## 概览

依据《安全承载力量化分析方法》,以作业计划、人员档案、请假信息、组织架构为输入,自动完成**日 / 周 / 月度 / 年度承载力测算**与**承载力分析报告生成**,输出四级预警(轻载≤50%、适度50%~75%、重载75%~90%、满载>90%,可超100%,>100% 落满载红)。**日历口径(v2.15)**:日维度(日报、日承载力、日期×单位矩阵、管理逐日、周报日段矩阵表)按计划覆盖的**全部自然日**展开——周六周日/法定节假日有计划的天照常参与计算,**周末承载力与日常算法一致、不剔除**;**周/月/年累加**时**分母**按工作日日历剔除周末与法定节假日,**分子**仍计入这些天的计划工时/实需人天(config「非工作日.是否剔除周末=true」+「法定节假日」清单可调,见 `references/维护手册_代码与计算全解.md`)。

测算与报告口径须与现网保持一致。核心公式与系数见 `references/承载力量化分析方法.md`,生成报告前先阅读该文件核对口径。

## 确定性（强制·任何人执行结果一致）

**同一输入 → 同一计算 → 同一版式。** 计算与排版是纯代码确定性流水线，不因执行人、对话轮次、临时观感调整而变化。

| 输入固定项 | 输出不变项 |
|---|---|
| 计划源 + `capacity_config.json` + 锚定日/时间范围 + 模板 | `calc_result` 数值、概况/明细/评述/矩阵/管理承载正文参数、图表数据与图位、分页与表/图尺寸策略 |
| （人工确认后）同一份 `advice.json` + 同一 `--office` | 建议章正文、函件落款 |

**禁止**：
- 为「这一次报告好看一点」改 `fillReport` / `pngCharts` / `office_chart` 里的魔术数或分支；
- 跳过 `runReports` 手改成品 Word；
- 同一数据源下因 AI「发挥」改公式、改阈值、改版心策略。

**允许因人而异的唯二处**（须先确认再注入；**单份 / 两份 / `--all` 同一规则**）：①文末 AI 辅助建议（`--advice` 覆盖本次每一份报告）；②所属机构 `--office`（报告与函件均必传，函件用于落款替换）。  
版面策略唯一源：`scripts/capacity/office_chart.py` 后半「版面策略」区（改观感只改该区，改完对所有人、所有次执行同时生效）。

## 数据来源选择规则（强制,每次执行先判定）

出报告 / 测算前**必须先判定计划数据来源**,二选一:

1. **用户上传了文件**(对话中提供了 `.xls`/`.xlsx` 文件路径,或明确说"用我上传的文件 / 用这个文件算")→ **一律用用户上传的文件**作为 `--source`,不得用内置数据。
2. **用户只说"出报告 / 输出报告 / 生成承载力报告"等、未提供文件** → 使用技能内置测试数据 `data/工作计划-测试数据.xls`(位于技能目录下 `data/` 文件夹),`--source` 指向该文件的绝对路径。

判定后在执行命令前向用户一句话说明本次使用的数据来源(内置测试数据 或 用户上传的某文件),再进入下方工作流。

## 直接运行（固化命令，免每次探索）

环境就绪后按下表**直接跑**，不必每轮重新探索脚本；`--config` 缺省自动找技能目录 `config/capacity_config.json`，日/周/月默认 `--chart native`（Word 可编辑竖柱写入 .docx，不经 PNG / 不经 WPS AddChart）。`<技能>` = 本技能根目录绝对路径。

| 诉求 | 命令 |
|---|---|
| 出全部主报告（日+周+月） | `... --all --report-date YYYY-MM-DD --advice advice.json --office "国网青岛供电公司安全生产委员会办公室" --out-dir 承载力报告` |
| 出两份 | `... --templates 报告-日,报告-周 --report-date YYYY-MM-DD --advice advice.json --office "…" --out-dir 承载力报告` |
| 出单份 | `... --template 报告-日\|周\|月 --report-date YYYY-MM-DD --advice advice.json --office "…" --out-dir 承载力报告` |
| 自定义时间范围 | `... --start YYYY-MM-DD --end YYYY-MM-DD --advice advice.json --office "…" --out-dir 承载力报告`（类型按范围长度自动判定；月报须整自然月） |
| 出函件 | `... --template 警示函-满载\|提示函-重载\|提示函-长期作业 --report-date YYYY-MM-DD --office "…" --out-dir 函件`（函件必 `--office`；报告另须 `--advice`） |

**唯一保留的必确认环节（单份 / 两份 / 全部同一规则）**：出成品前须按第 0 步展示【AI 建议草稿（覆盖本次每一份报告）+ 所属机构】→ 用户确认后带 `--advice` 与 `--office` 执行。`advice.json` 只需含**本次实际生成**的模板键（只出日报则仅「报告-日」；两份则两键；`--all` 则日/周/月三键均须非空）。缺 `--advice` / 缺对应键 / 缺 `--office` → `runReports` 直接 USAGE 失败，禁止回退 `DEFAULT_ADVICE`。其余「数据来源判定 + 命令拼装」按上表固化。

**编排实现（v2.27）**：`runReports` **同进程**调用各脚本 `main()`；多份（`--all` / `--templates`）与月报 native 的 `calcCapacity` **只跑一次**；整批挂共用 Word，**份与份之间 `recycle_shared_word`**；月报抛光优先复用共用实例。`repair_layout` 仍最多 8 轮。

## 工作流

对用户发来的"测算承载力 / 出承载力分析报告"请求,按以下步骤执行:

**触发方式（生成范围，一句话即可）**：
- **一句话生成全部**：用户说"生成/出承载力报告""出报告"（**不指定周期**）→ 默认生成**全部主报告**（报告-日 + 报告-周 + 报告-月，同锚定日期），一条命令 `runReports.py --all`（须 `--advice`+`--office`）串行产出。
- **指定单份**：用户明确"出日报告 / 周报 / 月报"→ 只出那一份，`runReports.py --template 报告-日|周|月`（须 `--advice` 含该键 + `--office`）。
- **指定两份**：用户明确"出日报和周报"等 → `--templates 报告-日,报告-周`（`--advice` 须含这两键 + `--office`）。
- **用户指定时间范围**：用户明确给出时间范围（"出 9 月 1 日到 10 日的报告""按 9/1~9/15 算承载力"）→ `runReports.py --start YYYY-MM-DD --end YYYY-MM-DD`，报告**按该范围判定，范围外的数据不写报告汇总**（概况/明细/评述/日分析/矩阵/管理承载/图表全部收敛到范围）：
  - 报告类型按范围长度自动判定：1 天→日报；2~7 天→周报；>7 天且覆盖整自然月→月报；**>7 天但不到整月→周报**（月报仅支持整自然月，非整月范围报错不生成）；用户明确说了日/周/月报时按用户说的来（日报多日范围报错）。
  - 锚定日默认取范围结束日（可用 `--report-date` 覆盖，**锚定日必须落在范围内**，范围外报错）；标题/文件名**保留原周次/月次命名**（周报标题括号内显示实际范围，如「2026年9月份第2周（9月1日至9月10日）」）。
  - 函件（警示函-满载/提示函-重载/提示函-长期作业）也按同一范围判定。
  - `--all` / `--templates` 不能与范围同用。
- 以上范围都遵守下方**第 0 步「生成前强制确认」**：先展示【本次报告的 AI 建议(真实分析) + 所属机构】→ 等用户确认/修改 → 再出。

0. **生成前强制确认（每次必做,不得跳过；单份/两份/全部同一规则）**:执行 `runReports.py` 出成品**之前**,必须先向用户展示并等待确认以下两项,用户确认 / 修改后**才可**执行;不得以默认值 / 模板文案跳过:
   - **报告 AI 辅助建议**（文末「四、辅助建议与风险管控提示」章）:按**本次实际要出的每一份**撰写并展示——只出日报只写「报告-日」；出两份写两键；`--all` 写日/周/月三键。须基于**当次 calc 数据真实分析**——点名超满/重载单位及其**具体百分比**、持续作业与高风险作业管控,**禁止**套用固定模板句或 `DEFAULT_ADVICE` 兜底句。
   - **所属机构确认**（报告与函件均必做）:展示默认「国网青岛供电公司安全生产委员会办公室」,用户确认或改为对应县公司安委办,以 `--office` 传入（确认默认名则原样传入）。函件落款替换依赖该参数；报告侧亦强制传入以证明已确认。
   确认完成前**不得**执行 runReports；代码层缺 `--advice`（报告）或缺 `--office`（报告/函件）会直接失败。

1. **收集输入数据**
   - 作业计划表(见 `references/作业计划数据字段说明.md`,31 字段模板)
   - 人员档案及效能系数 β(当前统一按 1.0 代替;接入真实人员效能数据源后再放开逐人取值)
   - 请假 / 出差 / 参会 / 培训信息
   - 组织架构(公司—工区—班组—人员)
   - 周期要求(日 / 周 / 月 / 年)与报告类型
   - 若某类数据用户未提供,明确列出缺口,不臆造数值。
   - 数据来源按上方「数据来源选择规则」判定:用户上传文件 → 用上传文件;用户仅要求出报告未给文件 → 用内置 `data/工作计划-测试数据.xls`。
   - 数据来源二选一:Excel 作业计划文件(`.xls`/`.xlsx`,按 `config/capacity_config.json`「输入解析」列映射读取)或接口 JSON(规范化 / 表格行形态),详见过下方「数据文件使用说明」。

2. **数据校验与预处理**
   - 核对必填字段:作业起止时间、作业风险等级、所属班组、工作负责人、作业时长、人数;
   - 作业时长 T 规范化:不足 1 小时按 1 小时,超过 8 小时按 8 小时;
   - 按日期拆分为日计划(多日工作按日归属)。

3. **承载力测算**
   - 人员效能折算系数 β 统一按 1.0 计(计算脚本 FORCE_BETA 开关,接入真实数据源后放开逐人读取);
   - 按日计算工作负责人、班组成员、班组、工区(加权)、管理承载力;
   - 按统计范围做周 / 月 / 年聚合;
   - 全部套用四级预警并标注(承载力可超 100%,>100% 落满载红);
   - **日历口径(v2.15)**:日维度日计算**不剔除周六周日与法定节假日**——计划覆盖的自然日逐日展开,周末/节假日有计划的天照常参与、周末承载力与日常一致;**周/月/年累加**只对**分母**按工作日日历剔除周末与法定节假日,分子仍累加这些天的计划工时/实需(config「非工作日.是否剔除周末=true」/「法定节假日」清单可调;is_workday 仅服务周期累加分母)。
   - **优先调用内置测算工具** `scripts/calcCapacity.py`(支持 `--demo` 演示、`.json` 规范化数据文件、`.xls`/`.xlsx` Excel 作业计划、`--api` 接口 JSON、`--config` 指定配置、`--period 日/周/月/年` 周期分桶输出;公式与输入解析统一读 `config/capacity_config.json`,改配置即生效;组织架构归一化可在配置「组织架构映射.是否启用=true」时输出"日期×单位"矩阵 matrix),避免手算误差;数据量大时务必用工具,人工核算结果需与工具输出比对一致后再用。

4. **报告生成**
   - 按 `references/报告模板字段说明.md` 与 SKILL.md 工作流组织章节(周报 / 月报 / 管控报告);
   - 生成月 / 周 / 年承载力柱状图与"日期 × 单位"统计表,重载 / 满载单元格着色;
   - 按国网公文版式输出 Word(方正小标宋标题、仿宋正文、固定行距、页码"— X —");
   - 若需套用现网官方 .doc 模板(日 / 周 / 月报告、警示函、提示函、长期作业函),改用 `scripts/fillReport.py` 把计算结果填充进 `templates/` 模板,无需手工重排版;字段与「一句话→参数」映射见 `references/报告模板字段说明.md`;正文参数由 `scripts/genReportParams.py` 依据 calc 结果自动生成(`--result`=calc 输出、`--source`=计划源、`--template 报告-日|周|月`、`--report-date` 锚定日期、`--config`、`--out` 参数 JSON):产出概况句(日计划项数/二级/三级)、三级及以上风险明细表(日表 6 列含**工作负责人真名 + 班组成员人数**、周表 7 列另含高风险作业时间;月/年不输出人员列)、作业承载评述段、真实管理承载力段(F_管理=Σ实需人天÷Σ可供人天,非通用文案)、周报日承载力矩阵表(已 **转置:一行一个日期、每一列=一个单位分类**,首列"日期"、列头为各分类名,替代模板旧「单位×日期」布局;fillReport 按「各单位日计划如表所示」锚点句定位目标表并动态补列,锚点句与表头写入均做防吞段处理;行按计划覆盖的**全部自然日**逐日列示(周六周日/法定节假日有计划的天照常参与日计算并显示数值,与日常口径一致,无计划日"-",不因周末/节假日被剔除;v2.3 起不再受「非工作日.是否剔除周末」开关影响));模板章节标题 / 表头已去除自带黄色高亮;

   - **执行者纪律**：用户要「完善技能/改规则」时改 SKILL+脚本并双份同步，**默认不把「再生成一遍报告」当交付**；用户明确说「出报告/生成报告」才跑 `runReports`。

   - 图组=引导句 + 图 + 图题：**紧贴**（空段近零、段间距清零）+ KeepWithNext；图题禁止单独段前分页。
   - **禁止**轴标题「项/%」倾斜竖排；**禁止**分类轴旋转。
   - 标签不写小数；单位只在刻度格式（百分图）体现。
   - 明细表：整表居中；列宽语义配方后拉满版心；字号/行距用 `DETAIL_FONT_PT`/`DETAIL_LINE_PT`（略紧给表后数量图腾位）；fillReport 保存前仍 `fit_tables_to_text`。
   - **月报弹性分页**：作业类型数量图优先跟计划表末同页（`polish_month_docx` 按剩余空间试高），**不**独霸空白页；「二、公司各单位」换页放图2+图3；「（二）周」+第1周同页；第2～5周各一页两图撑满；周标题前空段/空 PageBreak 自动清；建议章换页。

5. **AI 辅助建议（真实分析 + 两阶段强制确认 → 注入报告文末「四、辅助建议与风险管控提示」章）**
   - **真实分析(硬约束)**:建议必须**基于当次 calc 结果**(matrix 逐日/逐单位预警、超满/重载单位及其**具体百分比**、持续作业与高风险作业)实时撰写,**点名具体单位 + 具体数据**,给出针对性管控措施。**禁止**套用固定模板句、空泛套话;尤其**不得依赖 `genReportParams.DEFAULT_ADVICE` 兜底句**(「总体平稳 / 平稳可控」等三句仅为占位兜底,正式交付报告必须用真实分析建议替换,**不得留兜底句**)。不接任何外部 API。
   - **阶段一（草稿+确认,每次必做不得跳过）**：读 calc 结果 JSON（matrix / 逐日预警、超满 / 重载单位）与计划源，由 **AI（即当前生成者）** 结合当次数据面向「报告-日 / 周 / 月」各撰写 2~4 条建议，在对话中**完整展示**交用户逐条确认 / 修改 / 补充。
   - **阶段二（注入）**：用户确认后将终稿写入 `advice.json`（只含**本次要出的模板键**，如单日报仅 `{"报告-日":"…"}`，`--all` 则日/周/月三键均须非空真实建议），并以 `runReports.py --advice advice.json --office "…"` 生成；建议经 genReportParams 的 `--advice` 注入文末「四、辅助建议与风险管控提示」章（以模板占位段完整壳文本「本期辅助建议…建议占位符：ADVICE_BODY_2026」为 replace 键做**整段替换成纯建议正文**，成品不再残留「建议占位符：」字样）。缺键或缺 `--office` 时编排层直接失败，禁止用 `DEFAULT_ADVICE` 冒充已分析。
   - 每次出报告按**当次数据实时撰写**,该两阶段确认是**强制步骤**,不得跳过直接出报告。

## 数据文件使用说明

本技能支持**两种输入方式,可二选一,也可能交替执行**:

1. **Excel 作业计划文件**(`.xls`/`.xlsx`)— 按 `config/capacity_config.json`「输入解析」中的列映射读取主工作表(默认 `秋检计划`,表头第 0 行、数据从第 2 行起),时间列解析为 Excel 序列号;人员档案、组织架构可按配置开关加载。
   - **内置测试数据**:`data/工作计划-测试数据.xls`(技能目录下,含作业计划 + 人员档案 + 组织架构,可直接跑通全流程)。**用户只说"出报告 / 输出报告"而未提供文件时,默认用它**;用户上传了自己的作业计划文件时,改用用户上传的文件。
2. **接口 JSON** — 两种形态:规范化结构(人员 `persons`、作业计划 `plans`、请假 `absence`)或与 Excel 同构的表格行 `[{"列名": 值}, ...]`。

字段结构可先运行 `python scripts/calcCapacity.py --demo` 查看内置样例对照填写。报告内姓名一律输出真名(日/周明细列示工作负责人与班组成员人数,月/年不输出人员;**日历口径 v2.15:日维度不剔除周六周日与法定节假日、周末承载力与日常一致;周/月/年累加分母才按工作日日历剔除、分子保留这些天的计划工时**,config「非工作日」节可调);身份证号 / 联系方式 / 地址等敏感字段不进入计算与报告,请勿上传未脱敏的真实个人数据。

常用命令示例:

**输出落盘(v2.10)**:`--out-dir` 一律指向工作区「承载力报告」根目录(示例中的 `承载力报告`),runReports 自动在其下建「承载力报告{YYYYMMDD}」日期子文件夹(按生成当日)收纳全部成品,AI 建议 JSON 存「承载力报告/建议/」,中间产物在 `<日期夹>/_work/` 且默认清理、工作区不散放单个文件。

- `python scripts/calcCapacity.py 工作计划.xls` — Excel 按配置列映射测算(默认日口径)
- `python scripts/runReports.py --source "技能目录/data/工作计划-测试数据.xls" --all --report-date 2026-09-17 --advice 承载力报告/建议/advice.json --office "国网青岛供电公司安全生产委员会办公室" --out-dir 承载力报告` — 内置数据一键生成日+周+月（须 advice 三键 + office）
- `python scripts/runReports.py --source 用户上传的作业计划.xls --all --report-date 2026-09-17 --advice … --office "…" --out-dir 承载力报告` — 用户上传文件一键全部报告
- `python scripts/runReports.py --source 工作计划.xls --templates 报告-日,报告-周 --report-date 2026-09-01 --advice … --office "…" --out-dir 承载力报告` — 同批出两份
- `python scripts/runReports.py --source 工作计划.xls --start 2026-09-01 --end 2026-09-10 --advice … --office "…" --out-dir 承载力报告` — 自定义时间范围(10 天非整月→自动周报)
- `python scripts/calcCapacity.py 工作计划.xlsx --period 周` — .xlsx 输入并按周分桶输出 `periods`
- `python scripts/calcCapacity.py --api '{"rows":[...]}' --period 月` — 接口表格行输入、月度分桶
- `python scripts/runReports.py --source 工作计划.xls --template 报告-月 --report-date 2026-09-30 --advice … --office "…" --out-dir 承载力报告` — 单份月报
- `python scripts/runReports.py --source 工作计划.xls --template 提示函-重载 --report-date 2026-09-01 --office "国网青岛供电公司安全生产委员会办公室" --out-dir 函件` — 函件须 `--office`（满载/长期作业同理换模板）
- 需"日期 × 单位"矩阵(周/月报矩阵表)时:把 `config/capacity_config.json`「输入解析.组织架构映射.是否启用」改为 `true`,将 公司/工区/班组 归一化到 17 单位列,重跑后结果含 `matrix` 与逐日 `days`;若源 xls 自带「组织架构」sheet 且配置 `优先读取源表组织架构=true`,归列会先按 sheet 的班组/工区名+公司/工区上下文解析(未命中再走下方关键词规则),精度更高、规则维护量更低。

## 口径约束

- 工作负责人、班组成员承载力度量到班组/工作负责人层级;管理承载力按"实需人天 ÷ 可供人天"测算(同进同出、一般到位判定以业务口径确认为准);
- 报告落款单位"XX"命名规则、工时折算边界、成因归纳维度等以《待确认事项》为准,生成前若缺口径先向用户确认。

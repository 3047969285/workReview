# 安全作业承载力分析

## 概览

依据《安全承载力量化分析方法》,以作业计划、人员档案、组织架构为输入,自动完成**日 / 周 / 月度 / 年度承载力测算**与**承载力分析报告生成**。请假只来自规范化 JSON 的 `absence`,Excel 不加载请假。四级预警为轻载≤50%、适度50%~75%、重载75%~90%、满载>90%,可超过 100%,超过 100% 仍是满载。日维度按计划覆盖的全部自然日展开,周末与法定节假日有计划的天照常计算。周/月/年累加时分母按工作日日历剔除周末与法定节假日,分子仍计入这些天的计划工时(config「非工作日」可调,见 `references/维护手册_代码与计算全解.md`)。

测算与报告口径须与现网保持一致。核心公式与系数见 `references/承载力量化分析方法.md`,生成报告前先阅读该文件核对口径。

## 确定性（强制·任何人执行结果一致）

**同一输入 → 同一计算 → 同一版式。** 计算与排版是纯代码确定性流水线，不因执行人、对话轮次、临时观感调整而变化。

| 输入固定项 | 输出不变项 |
|---|---|
| 计划源 + `capacity_config.json` + 锚定日/时间范围 + 模板 | `calc_result` 数值、概况/明细/评述/矩阵/管理承载、建议章正文（由计算数字生成）、图表数据与图位、分页与表/图尺寸策略 |
| 同一 `--office` | 函件落款 |

**禁止**：
- 为「这一次报告好看一点」改 `fillReport` / `pngCharts` / `office_chart` 里的魔术数或分支；
- 跳过 `runReports` 手改成品 Word；
- 同一数据源下因 AI「发挥」改公式、改阈值、改版心策略。

**允许因执行人而不同的只有所属机构 `--office`**（报告与函件均必传，函件用于落款替换）。建议章正文不因人撰写的 advice JSON 而改变：`KEY_ADVICE_BODY` 由 `genReportParams._advice_from_numbers` 写入。`--advice` 仍可能被 `validate_advice_for_templates` 要求提供，以满足 CLI 兼容；JSON 里的自由正文不会抄进报告。  
版面策略唯一源：`scripts/capacity/office_chart.py` 后半「版面策略」区（改观感只改该区，改完对所有人、所有次执行同时生效）。

## 数据来源选择规则（强制,每次执行先判定）

出报告 / 测算前**必须先判定计划数据来源**,二选一:

1. **用户上传了文件**(对话中提供了 `.xls`/`.xlsx` 文件路径,或明确说"用我上传的文件 / 用这个文件算")→ **一律用用户上传的文件**作为 `--source`,不得用内置数据。
2. **用户只说"出报告 / 输出报告 / 生成承载力报告"等、未提供文件** → 使用技能内置测试数据 `data/工作计划-测试数据.xls`(位于技能目录下 `data/` 文件夹),`--source` 指向该文件的绝对路径。

判定后在执行命令前向用户一句话说明本次使用的数据来源(内置测试数据 或 用户上传的某文件),再进入下方工作流。

## 直接运行（固化命令，免每次探索）

环境就绪后按下表**直接跑**，不必每轮重新探索脚本；`--config` 缺省自动找技能目录 `config/capacity_config.json`，日/周/月默认 `--chart native`（Word 可编辑竖柱写入 .docx，不经 PNG / 不经 WPS AddChart）。`<技能>` = 本技能根目录绝对路径。

| 诉求 | 命令 |
|---|---|
| 出全部主报告（日+周+月） | `... --all --report-date YYYY-MM-DD --advice advice.json --office "国网青岛供电公司安全生产委员会办公室" --out-dir 承载力报告` |
| 出两份 | `... --templates 报告-日,报告-周 --report-date YYYY-MM-DD --advice advice.json --office "…" --out-dir 承载力报告` |
| 出单份 | `... --template 报告-日\|周\|月 --report-date YYYY-MM-DD --advice advice.json --office "…" --out-dir 承载力报告` |
| 自定义时间范围 | `... --start YYYY-MM-DD --end YYYY-MM-DD --advice advice.json --office "…" --out-dir 承载力报告`（类型按范围长度自动判定；月报须整自然月） |
| 出函件 | `... --template 警示函-满载\|提示函-重载\|提示函-长期作业 --report-date YYYY-MM-DD --office "…" --out-dir 函件`（函件必 `--office`；报告另须 `--advice`） |

**唯一保留的必确认环节（单份 / 两份 / 全部同一规则）**：出成品前须按第 0 步展示【AI 建议草稿（覆盖本次每一份报告）+ 所属机构】→ 用户确认后带 `--advice` 与 `--office` 执行。`advice.json` 只需含**本次实际生成**的模板键（只出日报则仅「报告-日」；两份则两键；`--all` 则日/周/月三键均须非空）。缺 `--advice` / 缺对应键 / 缺 `--office` → `runReports` 直接 USAGE 失败，禁止回退 `DEFAULT_ADVICE`。其余「数据来源判定 + 命令拼装」按上表固化。

**编排**：`runReports` **同进程**调用各脚本 `main()`；多份（`--all` / `--templates`）与月报 native 的 `calcCapacity` **只跑一次**；整批挂共用 Word，**份与份之间 `recycle_shared_word`**；月报抛光优先复用共用实例。`repair_layout` 仍最多 8 轮。

## 工作流

对用户发来的"测算承载力 / 出承载力分析报告"请求,按以下步骤执行:

**触发方式（生成范围，一句话即可）**：
- **一句话生成全部**：用户说"生成/出承载力报告""出报告"（**不指定周期**）→ 默认生成**全部主报告**（报告-日 + 报告-周 + 报告-月，同锚定日期），一条命令 `runReports.py --all`（须 `--advice`+`--office`）串行产出。
- **指定单份**：用户明确"出日报告 / 周报 / 月报"→ 只出那一份，`runReports.py --template 报告-日|周|月`（须 `--advice` 含该键 + `--office`）。
- **指定两份**：用户明确"出日报和周报"等 → `--templates 报告-日,报告-周`（`--advice` 须含这两键 + `--office`）。
- **用户指定时间范围**：用户明确给出时间范围（"出 9 月 1 日到 10 日的报告""按 9/1~9/15 算承载力"）→ `runReports.py --start YYYY-MM-DD --end YYYY-MM-DD`，报告**按该范围判定，范围外的数据不写报告汇总**（概况/明细/评述/日分析/矩阵/管理承载/图表全部收敛到范围）：
  - 报告类型按范围长度自动判定：1 天→日报；2~7 天→周报；>7 天且覆盖整自然月→月报；**>7 天但不到整月→周报**（月报仅支持整自然月，非整月范围报错不生成）；用户明确说了日/周/月报时按用户说的来（日报多日范围报错）。
  - 锚定日默认取范围结束日（可用 `--report-date` 覆盖，**锚定日必须落在范围内**，范围外报错）；标题/文件名**保留原周次/月次命名**。周报副标题由 `build_weekly_params` 写成不带全角括号的 `9月份第1周8月31日至9月6日` 这种形式。月报各周标题仍保留括号，如 `9月份第1周（8月31日至9月6日）`。
  - 函件（警示函-满载/提示函-重载/提示函-长期作业）也按同一范围判定。
  - `--all` / `--templates` 不能与范围同用。
- 以上范围都遵守下方**第 0 步**：先展示代码将写入的建议句和所属机构 → 等用户确认 → 再出。数字和单位必须来自当次计算，不要另写一套百分比。

0. **生成前确认（每次必做；单份/两份/全部同一规则）**:执行 `runReports.py` 出成品**之前**,向用户展示并等待确认:
   - **建议章正文**（文末「四、辅助建议与风险管控提示」）:由 `genReportParams._advice_from_numbers` 按当次项数、居前单位及百分比、峰值语气（满载/重载/适中/轻载）和管理承载力百分比生成。二级或三级项数为 0 的分句省略，不写「无」。没有三级及以上明细时，概况收尾为「当日/本周/当月三级及以上风险作业不单列明细。」AI 可以审读这句，**不得**改数字、改单位，也**不得**把 advice JSON 的自由散文当作报告正文。
   - **`--advice`**:`validate_advice_for_templates` / `DEFAULT_ADVICE` 仍可能要求 CLI 带上该文件（缺文件会 USAGE 失败）。文件内容不写入 `KEY_ADVICE_BODY`。
   - **所属机构**（报告与函件均必做）:展示默认「国网青岛供电公司安全生产委员会办公室」,用户确认或改为对应县公司安委办,以 `--office` 传入。
   确认完成前**不得**执行 runReports；代码层缺 `--advice`（报告）或缺 `--office`（报告/函件）会直接失败。

1. **收集输入数据**
   - 作业计划表(见 `references/作业计划数据字段说明.md`,31 字段模板)
   - 人员档案及效能系数 β：配置「强制统一β」在 `apply_formula_config` 之后由 `parse_person` 读取。当前为 true，每人 β 用默认 1.0；改为 false 后用人员档案「作业素养能力」。不是把 β 永久写死为 1.0。
   - 请假 / 出差 / 参会 / 培训：只在规范化 JSON 的 `absence` 里扣减。Excel 路径不加载请假，不会做请假扣减。
   - 组织架构(公司—工区—班组—人员)
   - 周期要求(日 / 周 / 月 / 年)与报告类型
   - 若某类数据用户未提供,明确列出缺口,不臆造数值。
   - 数据来源按上方「数据来源选择规则」判定:用户上传文件 → 用上传文件;用户仅要求出报告未给文件 → 用内置 `data/工作计划-测试数据.xls`。
   - 数据来源二选一:Excel 作业计划文件(`.xls`/`.xlsx`,按 `config/capacity_config.json`「输入解析」列映射读取)或接口 JSON(规范化 / 表格行形态),详见过下方「数据文件使用说明」。

2. **数据校验与预处理**
   - 核对必填字段:作业起止时间、作业风险等级、所属班组、工作负责人、作业时长、人数;
   - 作业时长 T 规范化:不足 1 小时按 1 小时,超过 8 小时按 8 小时;
   - 按日期拆分为日计划(多日工作按日归属)。

3. **承载力测算**
   - 人员效能折算系数 β 由「强制统一β」决定（当前 true → 默认 1.0；false → 档案「作业素养能力」）；
   - 按日计算工作负责人、班组成员、班组、工区(加权)、管理承载力;
   - 按统计范围做周 / 月 / 年聚合;
   - 全部套用四级预警并标注(承载力可超 100%,>100% 落满载红);
   - 日维度不剔除周六周日与法定节假日。周/月/年累加只对分母按工作日日历剔除,分子仍累加这些天的计划工时。`is_workday` 只服务周期累加分母。
   - **优先调用内置测算工具** `scripts/calcCapacity.py`(支持 `--demo` 演示、`.json` 规范化数据文件、`.xls`/`.xlsx` Excel 作业计划、`--api` 接口 JSON、`--config` 指定配置、`--period 日/周/月/年` 周期分桶输出;公式与输入解析统一读 `config/capacity_config.json`,改配置即生效;组织架构归一化可在配置「组织架构映射.是否启用=true」时输出"日期×单位"矩阵 matrix),避免手算误差;数据量大时务必用工具,人工核算结果需与工具输出比对一致后再用。

4. **报告生成**
   - 按 `references/报告模板字段说明.md` 与 SKILL.md 工作流组织章节(周报 / 月报 / 管控报告);
   - 生成月 / 周 / 年承载力柱状图与"日期 × 单位"统计表,重载 / 满载单元格着色;
   - 按国网公文版式输出 Word(方正小标宋标题、仿宋正文、固定行距、页码"— X —");
   - 若需套用现网官方 .doc 模板(日 / 周 / 月报告、警示函、提示函、长期作业函),改用 `scripts/fillReport.py` 把计算结果填充进 `templates/` 模板,无需手工重排版;字段与「一句话→参数」映射见 `references/报告模板字段说明.md`;正文参数由 `scripts/genReportParams.py` 依据 calc 结果自动生成(`--result`=calc 输出、`--source`=计划源、`--template 报告-日|周|月`、`--report-date` 锚定日期、`--config`、`--out` 参数 JSON):产出概况句(日计划项数/二级/三级)、三级及以上风险明细表(日表 6 列含**工作负责人真名 + 班组成员人数**、周表 7 列另含高风险作业时间;月/年不输出人员列)、作业承载评述段、真实管理承载力段(F_管理=Σ实需人天÷Σ可供人天,非通用文案)、周报日承载力矩阵表一行一个日期、每一列一个单位,首列「日期」,`max_units_per_table` 为 6。行覆盖计划区间内全部自然日,无计划为「-」。
   - **动态图表**:入口是 `scripts/nativeCharts.py`（`capacity.office_chart.native_main`）和 PNG 回退 `scripts/pngCharts.py` 的 `render|apply`。默认 `--chart native`：DrawingML 竖柱用 `manualLayout`，分类轴和数值轴 `crosses=min`，两轴共用原点。明细表「单位」列有最小宽度，`变电检修` 保持一行。周报矩阵 `max_units_per_table` 为 6。周图高度区间是 200–250pt。`apply_month_fixed_pages` 只在月报调用，日/周不调用。建议章由 `_advice_from_numbers` 写入。
   **日/周/月可编辑图表（默认 `--chart native`）**: DrawingML **国网竖柱**（横轴=类别、纵轴数值）；**无「项/%」轴标题**；图内宋体小四；数据标签整数；分类轴横排不倾斜；无外框无图例。图高区间由 `capacity/office_chart.py` 版面策略区统一给出（注入初值 + COM 按版心剩余空间动态定稿）。正文 29pt/模板字体不改。回退 `--chart png` 走 `pngCharts.py`。

   **固定流水线（强制·人机分工·可复现）**:
   - **确定性**：同一 `--source` + `--config` + `--report-date`/`--start/--end` + 模板 → 任何人多次执行，计算与正文/图表数据/版式策略一致；禁止为单次报告改代码或手改成品。
   - **代码自动完成**：`runReports.py` 一键贯通 calc → params → fillReport → `nativeCharts`（`office_chart.native_main`）。月报才调用 `apply_month_fixed_pages`，再 `reflow_month_type_chart` → `polish_month_docx`；日/周不调用 `apply_month_fixed_pages`。表/图策略**全部读 `capacity/office_chart.py` 版面策略区**；禁止在 fillReport / pngCharts 再写死 pt。
   - **人工确认**：所属机构 `--office`（报告与函件均必传）。建议章由代码按计算数字生成，AI 只审读、不改写数字和单位。`--advice` 仍可能为 CLI 必填，但其 JSON 正文不进入报告。
   - **一键编排**: `scripts/runReports.py`（`--source`、`--template` / `--templates` / `--all`、`--report-date`、`--config`、`--advice`、`--office`、`--out-dir`、`--chart native|png`、`--keep`）；多份之间 `recycle_shared_word`；PNG 回退用 `pngCharts.py render|apply`。
   - **执行者纪律**：用户要「完善技能/改规则」时改 SKILL+脚本并双份同步，**默认不把「再生成一遍报告」当交付**；用户明确说「出报告/生成报告」才跑 `runReports`。

   **排版（策略源=`capacity/office_chart.py` 版面策略区）**:
   - 正文：模板字体 + **29pt 固定行距**，禁止改。
   - 图组=引导句 + 图 + 图题：**紧贴**（空段近零、段间距清零）+ KeepWithNext；图题禁止单独段前分页。
   - **禁止**轴标题「项/%」倾斜竖排；**禁止**分类轴旋转。
   - 标签不写小数；单位只在刻度格式（百分图）体现。
   - 明细表：整表居中；列宽语义配方后拉满版心；字号/行距用 `DETAIL_FONT_PT`/`DETAIL_LINE_PT`（略紧给表后数量图腾位）；fillReport 保存前仍 `fit_tables_to_text`。
   - **月报弹性分页**：作业类型数量图优先跟计划表末同页（`polish_month_docx` 按剩余空间试高），**不**独霸空白页；「二、公司各单位」换页放图2+图3；「（二）周」+第1周同页；第2～5周各一页两图撑满；周标题前空段/空 PageBreak 自动清；建议章换页。
   - **输出目录**:工作区只留文件夹、不散放单个文件。`--out-dir` 指向工作区「承载力报告」根目录,runReports **自动在其下建「承载力报告{YYYYMMDD}」(按生成当日)** 日期子文件夹收纳**全部成品**(同批生成的日/周/月报告合并入同一日期夹),中间产物在 `<日期夹>/_work/` 且**默认清理(只保留最终文件)**;若流水线仍写出 advice JSON，它只满足 CLI 校验，不作为建议章正文;
   - **函件成套(可选)**:命中预警的单位 / 连续超限工作负责人自动发函 — `scripts/runReports.py` 传 `--template 警示函-满载|提示函-重载|提示函-长期作业` 即走函件三步编排(`calcCapacity` → `scripts/genLetterParams.py` 生成逐封填充参数 → `fillReport` 逐封成稿,无图表):满载=周期内单位承载力峰值 >90%(含>100%)(警示函)、重载=(75,90%](提示函-重载,两档不重复发)、长期作业=某工作负责人周期内连续在岗作业天数 ≥ 配置阈值(默认 5 天,每人一函);作业清单附表 10 列(序号/工作日期/工作内容/电压等级/风险等级/工作负责人/作业班组/自有人员数量/外包施工单位/外包人数),外包两列填「—」、工作负责人输出真名、文件名非法字符自动转全角;无命中时优雅空返回(非错误)。**发函与出报告均须先向用户确认所属机构**：默认「国网青岛供电公司安全生产委员会办公室」，县公司安监部账号时传对应县公司安委办全名(`--office` 必填，缺则 USAGE 失败)。组织架构若 `优先读取源表组织架构=true` 且源为 Excel,归列自动先读源表「组织架构」sheet(班组/工区名 + 公司/工区上下文消歧),sheet 未命中再走关键词规则;
   - 日 / 周承载力争细化到具体工作负责人真名列示,并含班组成员人数;月、年度仅到班组 / 工区 / 公司层面,不输出人员姓名与人数列(报告内姓名一律输出真名)。

5. **建议章（代码生成，AI 只审读）**
   - 正文由 `genReportParams._advice_from_numbers` 写入模板占位 `KEY_ADVICE_BODY`。句子只用本次项数、居前单位及百分比、峰值语气（满载 ≥90 / 重载 ≥75 / 适中 ≥50 / 轻载）和管理承载力百分比。二级或三级为 0 时不写该等级分句。没有可列明细时，概况句为「当日/本周/当月三级及以上风险作业不单列明细。」
   - AI 可以审读这句是否把算出的单位和百分比说清楚。数字和单位必须来自计算，不要另编一段 advice JSON 散文灌进报告。
   - `--advice` 仍可能被 `validate_advice_for_templates` 要求存在（`DEFAULT_ADVICE` 留作 CLI 兼容）。缺文件或缺 `--office` 时编排层失败。JSON 文本不是建议章正文。

## 数据文件使用说明

本技能支持**两种输入方式,可二选一,也可能交替执行**:

1. **Excel 作业计划文件**(`.xls`/`.xlsx`)— 按 `config/capacity_config.json`「输入解析」中的列映射读取主工作表(默认 `秋检计划`,表头第 0 行、数据从第 2 行起),时间列解析为 Excel 序列号;人员档案、组织架构可按配置开关加载。
   - **内置测试数据**:`data/工作计划-测试数据.xls`(技能目录下,含作业计划 + 人员档案 + 组织架构,可直接跑通全流程)。**用户只说"出报告 / 输出报告"而未提供文件时,默认用它**;用户上传了自己的作业计划文件时,改用用户上传的文件。
2. **接口 JSON** — 两种形态:规范化结构(人员 `persons`、作业计划 `plans`、请假 `absence`)或与 Excel 同构的表格行 `[{"列名": 值}, ...]`。

字段结构可先运行 `python scripts/calcCapacity.py --demo` 查看内置样例对照填写。报告内姓名一律输出真名(日/周明细列示工作负责人与班组成员人数,月/年不输出人员;日维度含周末与法定节假日,周/月/年累加分母按工作日剔除);身份证号 / 联系方式 / 地址等敏感字段不进入计算与报告,请勿上传未脱敏的真实个人数据。

常用命令示例:

**输出落盘**:`--out-dir` 指向工作区「承载力报告」根目录,runReports 在其下建「承载力报告{YYYYMMDD}」收纳成品。建议章正文由计算生成。中间产物在 `<日期夹>/_work/` 且默认清理。

- `python scripts/calcCapacity.py 工作计划.xls` — Excel 按配置列映射测算(默认日口径)
- `python scripts/runReports.py --source "技能目录/data/工作计划-测试数据.xls" --all --report-date 2026-09-17 --advice 承载力报告/建议/advice.json --office "国网青岛供电公司安全生产委员会办公室" --out-dir 承载力报告` — 内置数据一键生成日+周+月（须 advice 三键 + office）
- `python scripts/runReports.py --source 用户上传的作业计划.xls --all --report-date 2026-09-17 --advice … --office "…" --out-dir 承载力报告` — 用户上传文件一键全部报告
- `python scripts/runReports.py --source 工作计划.xls --templates 报告-日,报告-周 --report-date 2026-09-01 --advice … --office "…" --out-dir 承载力报告` — 同批出两份
- `python scripts/runReports.py --source 工作计划.xls --start 2026-09-01 --end 2026-09-10 --advice … --office "…" --out-dir 承载力报告` — 自定义时间范围(10 天非整月→自动周报)
- `python scripts/calcCapacity.py 工作计划.xlsx --period 周` — .xlsx 输入并按周分桶输出 `periods`
- `python scripts/calcCapacity.py --api '{"rows":[...]}' --period 月` — 接口表格行输入、月度分桶
- `python scripts/runReports.py --source 工作计划.xls --template 报告-月 --report-date 2026-09-30 --advice … --office "…" --out-dir 承载力报告` — 单份月报
- `python scripts/runReports.py --source 工作计划.xls --template 提示函-重载 --report-date 2026-09-01 --office "国网青岛供电公司安全生产委员会办公室" --out-dir 函件` — 函件须 `--office`（满载/长期作业同理换模板）
- 需"日期 × 单位"矩阵(周/月报矩阵表)时:把 `config/capacity_config.json`「输入解析.组织架构映射.是否启用」改为 `true`,将 公司/工区/班组 归一化到 17 单位列,重跑后结果含 `matrix` 与逐日 `days`;若源 xls 自带「组织架构」sheet 且配置 `优先读取源表组织架构=true`,归列会先按 sheet 的班组/工区名+公司/工区上下文解析(未命中再走下方关键词规则),精度更高、规则维护量更低。

## 口径约束

- 工作负责人、班组成员承载力度量到班组/工作负责人层级;管理承载力按"实需人天 ÷ 可供人天"测算(同进同出、一般到位判定以业务口径确认为准);
- 报告落款单位"XX"命名规则、工时折算边界、成因归纳维度等以《待确认事项》为准,生成前若缺口径先向用户确认。

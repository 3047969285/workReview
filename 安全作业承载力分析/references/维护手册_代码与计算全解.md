## 1.1 全函数目录（读这一节即懂每个函数）

> 一行一函数、签名从简、代码为准；`_` 前缀为模块内私有。计算内核在 `scripts/capacity/`，可执行脚本在 `scripts/`。数据流：`输入 → parsing/excelLoader → WorkDataset → CapacityService → 结果JSON → 报告脚本`。

### capacity/constants.py（常量与异常）
- `is_workday(d)`：该日是否计入**周期累加分母**（剔周末[EXCLUDE_WEEKENDS]与 STATUTORY_HOLIDAYS）；日维度不调用。
- 常量：`STD_HOURS_PER_DAY=8`、`MIN/MAX_WORK_HOURS[1,8]`、`DEFAULT_BETA=1.0`、`FORCE_BETA=True`、`LEADER_LOAD_CAP=999`、`DENOM_EPS`、`RISK_COEF`(θ表)、`ALERT_RULES`(四级)、`REPORT_UNITS`(17单位)、各 `*_FIELD_ALIASES`(列别名)。
- 异常：`CapacityError`(基类，带 code/context/to_payload) 及 `UsageError/InputDataError/FileAccessError/FileContentError/OutputWriteError`；错误码 `ERR_*`、退出码 `EXIT_*`、`_ERROR_EXIT` 映射。

### capacity/models.py（不可变领域模型 @dataclass frozen）
- `PersonRecord`：姓名/班组/beta/is_leader/county/work_area/role/team_kind（班组类型）。
- `PlanRecord`：名称/班组/leader/`leader_count`(负责人需求数量)/members/hours/risk/plan_type/start/end/company/work_area。
- `AbsenceRecord`：姓名/起/止（不在岗）。
- `WorkDataset`：persons/plans/absences 三元组，上层唯一数据源。

### capacity/config.py（配置加载与写回）
- `load_config(path)`：读 JSON 配置；缺省自动找，非法抛异常。
- `apply_formula_config(cfg)`：把「公式与计算参数」写回 constants 模块级系数（θ/预警/非工作日/管理系数）。
- `default_config_path()`：向上查 `config/capacity_config.json`。
- `_cfg_get(node,key,default)`：多级安全取值。
- 数据：`DEFAULT_INPUT_CONFIG`(内置输入解析缺省)、`_PLAN_CANON`(逻辑字段→模型字段)。

### capacity/parsing.py（解析校验：原始→模型）
- `parse_date(v)` / `coerce_date(v,mode)`：日期解析（含 Excel 序列号 1899-12-30 基准）。
- `to_float` / `clamp_hours` / `_parse_bool` / `_pick` / `_require_date`：字段转换与别名取值。
- `parse_person` / `parse_plan` / `parse_absence`：单条校验（含 leader_count 数量解析、时长 clamp[1,8]）。
- `build_dataset(raw)`：{persons,plans,absence}→WorkDataset。
- `read_dataset_file(path)`：读 JSON 文件→WorkDataset。
- `_rows_to_plans(rows,cfg)` / `_rows_from_interface` / `read_interface_dataset`：表格行/接口 JSON→计划。

### capacity/excelLoader.py（Excel 双引擎）
- `_open_workbook(path)`：按扩展名选 xlrd(.xls/.xlsm) / openpyxl(.xlsx)。
- `_sheet_nrows/_sheet_ncols/_sheet_cell/_find_workbook_sheet/_xls_rowdicts`：跨引擎取值。
- `_build_xls_persons(wb,cfg)`：解析人员表（姓名/班组/角色必填，β/工区/职务可选）。
- `_parse_workbook`：主表+人员表→WorkDataset。
- `read_sheet_rows(path,sheet,...)`：读任意 sheet 原始行（组织架构/展示列复用）。
- `read_xls_persons(path,cfg)`：只读人员表原始记录。
- `read_xls_dataset(path,cfg)`：Excel 作业计划→WorkDataset（入口）。

### capacity/coefficients.py（系数与预警）
- `risk_theta(risk_level, plan_type=None, content=None)`：工作内容或作业类型去空白后正好是「装表接电」时 θ=RISK_COEF「装表接电」0.2；空或「无」为 0；未知回退四级 1.0。含「装表」但不等于「装表接电」的不改判五级。
- `build_person_beta(persons)`：班组→姓名→β 索引 + 班组→负责人β。
- `classify_alert(pct)`：走 `ALERT_RULES`。套配置后只有 90/75/50，大于 90（含大于 100）为满载，无停工档。constants 里套配置前的预置表仍含「停工(超满载)」，加载配置后被替换。

### capacity/roster.py（班组真实分母 / 负责人真名）
- `clean_team_token` / `split_team_tokens`：班组名清洗（去 -N 抽调）与多班组拆分。
- `build_roster_index(persons)`：班组→{beta_by_name,leaders,areas,counties}。
- `resolve_team(roster,team)`：任一班组未命中返回 None。函件仍用这一严格口径；承载力计算不靠它整条丢计划。
- `split_team_assignments` / `iter_plan_team_slices`：按「班组名-人数」拆开。未匹配班组跳过；负责人数量只记在第一个匹配班组；每条用该班组的「-数字」和该班组 Σβ。
- `filter_roster_matchable(dataset,roster)`：一个班组都匹配不到才整条剔除；部分对不上的计划保留。
- `roster_staff(roster,team,absent)`：当日可用人数（该班组 Σβ − 不在岗）。Excel 不加载请假，absence 只来自 JSON。

### capacity/org.py（组织架构归 17 单位列）
- `UnitNormalizer`：归一化器——
  - `load_sheet(rows)`：载入「组织架构」sheet 目录（同名多子树并存）。
  - `unit_of(values)`：公司/工区/班组→单位列（sheet 上下文消歧 → 关键词兜底）。
  - `short_name(values)`：取公司/工区/班组简称。
  - `_resolve_context/_find_row/_pick_candidate/_unit_from_row/_match/_slice/_short_company`：消歧与匹配内部件。
- `load_org_sheet_rows(source,cfg)`：配置启用时读源表「组织架构」sheet。
- `filter_matchable(dataset,normalizer)`：剔除归「其他」的计划。

### capacity/calculator.py（★计算核心）
- `_days_between` / `_workdays_between`：自然日 / 工作日展开。
- `period_unit_caps_from_daily` / `period_manage_caps_from_days`：图表与评述的周期口径（Σ自然日 / 工作日天数；管理=Σ实需÷(在册×工作日)）。
- `_day_absent_names` / `_on_day_plans` / `_team_denom`：当日不在岗 / 生效计划 / 班组分母(8×可用人数)。
- `calc_team_staff`：班组可用人数（真实在册 − 当日不在岗）。
- `calc_leader_capacity`：负责人承载力（需求工时 ÷ 负责人可用人天，≤999）。
- `calc_member_capacity`：班组成员承载力（成员工时 ÷ 分母）。
- `calc_team_capacity`：班组综合 `max(负责人,成员)`+班组类型扩展，含预警与单位归列。
- `calc_area_capacity`：工区加权承载力（权重=自身占比）。
- `calc_day`：单日逐班组聚合（第二遍做每人 8h 截断）。
- `calc_period`：周/月/年聚合（分子=全部自然日计划工时，分母按工作日日历）。
- `calc_period_buckets`：按周(ISO)/月/年分桶。
- `build_matrix_day`：单日「日期×单位」矩阵行。
- `_manage_occupancy`：单现场管理占用（同进同出 2 / 一般 1）。
- `managers_by_unit`：各单位在家管理人数，只展示，不进入分母。
- `staff_by_unit`：各单位在册 Σβ（管理承载力分母）。
- `management_demand_by_day`：逐日各单位实需人天（自然日）。
- `_mgmt_unit_summary` / `_mgmt_range_summary`：单位 / 区间管理承载力汇总（分子=全部自然日实需，分母天数按工作日）。
- `build_management`：管理承载力全量输出（managers/overall/periods/days）。
- `CapacityService`：薄调度——`__init__`(β索引/归一化器/剔除不匹配)、`calc_day`/`calc_period`、`summarize(period)`（输出 persons_beta/days/periods/matrix/management）。

## 2. 计算规则速查（改哪看哪）

### 2.1 系数与工时

| 项 | 默认 | 修改入口（config） |
|---|---|---|
| 标准日工时 | 8h | 公式节.标准日工时 |
| 时长 T 边界 | [1h,8h]（不足1h按1h，超8h按8h） | 公式节.工时边界 |
| 人员效能 β | 「强制统一β」在 parse_person 读取。当前 true → 默认 1.0；false → 档案「作业素养能力」。不是永久写死 1.0 | 公式节.强制统一β / 默认人员效能系数β |
| 班组可用人数分母 | 按班拆开后取该班组在册 Σβ。未匹配班组跳过；仅全部未匹配才整条不计算。不设默认满编 | 见 `roster.iter_plan_team_slices` |
| 负责人钳制 | ≤999 | 公式节.负责人承载力上限 |

### 2.2 作业风险系数 θ（`risk_theta`）

| 等级 | 二级 | 三级 | 四级 | 五级 | 装表接电 |
|---|---|---|---|---|---|
| θ | 1.5 | 1.2 | 1.0 | 0.8 | 0.2 |

- 工作内容或作业类型去掉首尾空白后正好是「装表接电」时，θ=0.2，不看作业风险等级。其它文字按作业风险等级取值。
- 作业风险等级为空或「无」→ θ=0。未知等级回退四级 1.0。二级 1.5、三级 1.2、四级 1.0、五级 0.8 不变。
- 「电网风险等级」（秋检计划第 17 列，从 0 计第 16 列）不参与。只有「作业风险等级」（第 18 列，从 0 计第 17 列）进入 θ、管理占用、报告明细和函件。

### 2.3 日承载力（分子/分母，标准 8h）

```
负责人工时 += T·θ·β_leader×leader_count；成员工时 += T·θ·1.0×members
巡视工时（作业∈巡视）　+= T·members；操作工时（∈倒闸/操作）+= T·members
可用人数 = 该班组在册Σβ − 当日不在岗Σβ（不在岗只来自 JSON absence；Excel 路径 absence 为空）
```
- **负责人承载力** = `min(负责人工时 / (8×该班组工作负责人数), 999)`（工作负责人数=人员档案中该班组角色含「工作负责人」的真名个数；分子按 `计划所需负责人数量 leader_count` 计需求。多班组时 leader_count 只记在第一个匹配班组）
- **班组分母**：`iter_plan_team_slices` 按班拆开。每条用该班组名后的「-数字」作人数、该班组 Σβ 作分母。未匹配班组跳过。一个班组都匹配不到才整条不计算
- **成员承载力** = `成员工时 / (8×可用人数)`（成员工时=0 → 0）
- **班组承载力**：由人员信息「班组类型」经 `PersonRecord.team_kind` 与 `_team_kind_for` 决定。检修施工 `max(负责人,成员)`；运检合一 `max(负责人,成员)+巡视`；变电运维 `操作+巡视`。没填或并列回退配置「默认班组类型」（当前检修施工）。「调控」走检修施工分支。调度/供服公式没有实现在 `calculator.py`
- **工区承载力** = `Σ(v_i·(v_i/Σv))`（权重=自身占比；全 0 不输出 area）
- **每人每日实际工时 ≤8h**：超过 8h 按 `8/ΣT` 压缩，`calc_day` 聚合后第二遍处理：
  - 工作负责人**按人分组**：单日跨多个作业 ΣT>8h 时，各作业加权需求按 `8/ΣT` 比例压缩后再求和（`负责人分组` 字典）；
  - 班组成员：按“当日班组工作日小时合计 ΣT”为每人实际工时（班组人员同做本班组全部作业），成员工时/巡视/操作占用按 `8/ΣT` 比例压缩（= 计划口径「ΣT×人数 > 8×人数」消去人数后即 ΣT>8）。

### 2.3.1 工作日日历（日维度按自然日，周期累加分母剔除周末与法定节假日）

统一抽象为 `C.is_workday(d)`（constants.py）：
- **默认剔除**：`constants.EXCLUDE_WEEKENDS=True`；config「非工作日.是否剔除周末」现值 **true**；config「非工作日.法定节假日」现列 **2026 全年**放假清单（元旦/春节/清明/劳动/端午/中秋/国庆），由 `config.apply_formula_config` 写入 `STATUTORY_HOLIDAYS`。
- `is_workday(d)` = 非周六周日（EXCLUDE_WEEKENDS 时）且 `d ∉ STATUTORY_HOLIDAYS`。需完全按计划时间算时，把「是否剔除周末」置 false 且清空节假日清单。

**`is_workday` 只作用于周期累加分母，日维度按自然日展开**：
- 日维度（`CapacityService.summarize` 的 `day_set`→`days`/`matrix`、`management_demand_by_day` 的 `management.days`、周报矩阵 `_matrix_table`、日分析 `_week_over_analysis`）走 `_days_between`，含周六周日/法定节假日，有计划的天照常算、周末承载力与日常一致；
- 周期累加（`calc_period`、`_mgmt_range_summary`/`genReportParams._mgmt_aggregate`）：**分母**走 `_workdays_between`/`is_workday` 剔除周末与法定节假日；**分子**按区间全部自然日累加计划工时/实需人天。

计划本身的排期日期（如明细表“工作日期”、函件作业清单附表）为**计划事实**，按原日期照实展示、永不因日历改写。

### 2.4 周期聚合（周/月/年）

分子按区间**全部自然日**叠加（周六日/法定节假日有计划的工时照计）；**分母按工作日日历剔除周末+法定节假日**（`is_workday`，见 §2.3.1）；`F_班组` 与日口径相同（按班组类型：检修施工取 max(负责人,成员)，运检合一再加巡视，变电运维为操作+巡视）。分桶键 周=ISO周 / 月=`YYYY年M月` / 年=`YYYY年`。**周期聚合不做每人 8h 截断**（现网简化口径；日/周/月报告正文的 `periods` 块同此，与日明细 §2.3 的 8h 压缩有差异，属既定口径）。周/月图表与评述使用同一套分子分母：单位柱高=Σ自然日日承载力%÷工作日天数；管理柱高=Σ实需÷(在册×工作日天数)；不是有数据日的算术平均。区间无工作日时分母改用自然日（周六日报不画成 0）。

### 2.5 预警分级（`classify_alert`，严格>降序命中）

| 轻载(蓝) | 适度(黄) | 重载(橙) | 满载(红) |
|---|---|---|---|
| ≤50% | 50~75% | 75~90% | >90%（可超过 100%，仍为满载。配置套用后没有停工档） |

边界注意：恰为 50/75/90 判**上一档**（严格大于）。承载力可超 100% 正常显示（例：某班组成员工时 145.7% → 预警「满载」）。

### 2.6 日期×单位矩阵（组织架构启用时输出）

单位承载力 = 该单位各班组成员能力**加权均值**（权重=自身占比），未命中归「其他」。

### 2.6.1 组织架构归列（sheet 数据驱动 + 关键词兜底）

归列把计划的 公司/工区/班组 三字段收敛到报告矩阵表 17 单位列，解析优先级：

1. **源表「组织架构」sheet 上下文消歧**（配置 `组织架构映射.优先读取源表组织架构=true` 且源为 Excel 时启用）：按班组名/工区名在 sheet（市公司/县公司/县公司简称/单位（工区）/工区简称/班组/班组简称）中收候选行，用 计划公司→县公司子树、工区→单位（工区）/工区简称 逐级打分，唯一且得分>0 才采纳——即便同名行在 sheet 唯一出现也必须与计划公司子树重叠，防「配电工程四队」等外部承接队在直属计划下被错归到县公司。命中行的「县公司简称∈单位清单」直接归该县公司；否则对行内 单位（工区）/工区简称/班组/班组简称 名走关键词归属规则。
2. **关键词归属规则**（`班组归属规则` 顺序匹配任一「包含」词）——sheet 未命中时的兜底。
3. **单位清单包含匹配**（取最长命中）——两路规则均未命中时兜底。

实现 `org.UnitNormalizer.load_sheet(rows)` + `unit_of(values)`，sheet 目录只负责「班组/工区名 + 上下文 → 单位（工区）」，「单位（工区）→ 归列单位」仍由 `_match` 完成，二者解耦；sheet 缺失/未启用时优雅回退纯关键词路径，不阻断流水线。

### 2.7 管理承载力 F_管理（输入解析.管理承载力.是否启用=true 时输出 management 块）

```
实需人天 = Σ 每个现场每日占用人天（需同进同出=2 / 一般到位=1），多日作业按日叠加
可供人天 = 单位全部在册可用人员 Σβ × 工作日天数
F_管理   = 实需人天 ÷ 可供人天（预警同 §2.5 四级分级）
```

- **同进同出判定**：作业风险等级命中「需同进同出风险等级」（默认 二级/三级）占 2 人天，其余（四级/五级等）占 1 人天。
- **在家管理人员数**：人员档案中 角色/职务 任一命中「管理岗关键字」（管理/主任/副主任/书记/经理/总经理/副总经理/专责…）者计入；按 单位(工区) 优先、县公司 兜底 归到报告 17 单位列；单位无档案按 0 计（**无默认管理人数回退**，实事求是不瞎设）。该人数只展示。分母是 `staff_by_unit` 的单位在册 Σβ × 工作日天数。
- **输出结构**：`management = {enabled, managers:{单位:{在家管理人员数}}, overall:{单位:{实需人天,可供人天,在家管理人员数,管理承载力,预警}}, periods:[{period,start,end,units:{...}}], days:{日期:{单位:{实需人天,管理承载力,预警}}}}`。报告只在 日/周/月 三份报告「单位承载力分析」末尾生成「2.管理承载力分析」自然段，3 份通知函无此段。
- **加载联动**：**人员档案现为必要数据源，Excel 一律加载**（班组真实分母 + 工作负责人真名均来自此，与 强制统一β / 管理承载力开关无关）；`管理承载力.是否启用=true` 时额外输出「在家管理人员数」与管理承载段落。

## 5. 报告生成链路

```
日/周/月默认 --chart native：
  calcCapacity → genReportParams → fillReport → nativeCharts.py
  （capacity.office_chart.native_main，DrawingML 竖柱写入 .docx）
  月报在注入后调用 apply_month_fixed_pages，再 reflow_month_type_chart、polish_month_docx。
  日/周不调用 apply_month_fixed_pages。
PNG 回退 --chart png：
  calcCapacity → genReportParams → pngCharts.py render → fillReport → pngCharts.py apply
一键：runReports.py --source 计划 --template 报告-日|周|月（或 --all / --templates）
      --report-date [--start --end] [--chart native|png] --advice --office --out-dir

函件：runReports.py --template 警示函-满载|提示函-重载|提示函-长期作业
  calcCapacity → genLetterParams → 逐封 fillReport（无图表）
```

图表：`office_chart` 用 `manualLayout`，分类轴与数值轴 `crosses=min`，两轴共用原点。明细表「单位」列有最小宽度，「变电检修」保持一行。周报矩阵 `max_units_per_table` 为 6。周图高度区间 200–250pt。

| 脚本 | 要点 |
|---|---|
| `genReportParams.py` | 读 calc 结果与计划源，产出 `{replace, paragraph_replace, tables}`。概况句含计划总数、二级、三级（为 0 的等级分句在建议章中省略）。三级及以上明细：日表 6 列、周表 7 列，含工作负责人真名与班组成员人数；月表 5 列，不含人员。高风险作业时间是日期加单元格内换行再加（N天）。周报矩阵行是日期、列是单位，`max_units_per_table` 为 6，行覆盖区间内全部自然日，无计划为「-」。周报副标题不带全角括号，例如 `9月份第1周8月31日至9月6日`；月报各周标题保留括号。建议章 `KEY_ADVICE_BODY` 由 `_advice_from_numbers` 写成计算句。`--advice` 可满足 CLI 校验，JSON 自由正文不进入报告。没有三级及以上明细时，概况收尾为「当日/本周/当月三级及以上风险作业不单列明细。」 |
| `genLetterParams.py` | 按模板筛选满载、重载、长期作业，逐封产出 fillReport 参数。风险列只用「作业风险等级」。无命中时 `letters` 为空数组。作业清单外包两列填「—」，工作负责人输出真名。 |
| `fillReport.py` | 6 份模板只读填充。`--demo` 里周报标题示例为 `9月份第3周9月1日至6日`（无全角括号）。空明细表删除。矩阵单位列超过 `max_units_per_table` 时纵向分块。 |
| `pngCharts.py` | PNG 入口：`render` 出竖柱，`apply` 插入成品。 |
| `nativeCharts.py` | 薄入口，转到 `office_chart.native_main`。日、周、月默认可编辑竖柱；月报才做固定分页抛光。 |
| `runReports.py` | 同进程编排。日/周/月默认 `--chart native` 输出 `.docx`。`--chart png` 走 `pngCharts.py`。`--all` 只计算一次。报告需要 `--advice` 与 `--office`；函件需要 `--office`。 |

报告结构（周报/月报/秋检五章）与版式口径见《报告模板字段说明.md》与 SKILL.md 工作流；**日/周明细到 工作负责人真名 + 班组成员人数，月/年不输出人员（明细无负责人/人数列）；姓名一律真名（不脱敏）**。

### 5.1 函件触发规则（三份官方函件）

函件与报告共用同一 calc result（matrix）与计划源，单位口径一致；`runReports --template` 传入函件名即走函件三步编排，无图表。触发与占位要点：

| 函件模板 | 触发规则 | 命中粒度 | 数量 |
|---|---|---|---|
| 警示函-满载 | 周期内单位承载力**最大值 >90**（含 >100） | 单位 | 每命中单位一封 |
| 提示函-重载 | 周期内单位承载力最大值在 **(75, 90]** | 单位 | 每命中单位一封（与满载两档不重复发） |
| 提示函-长期作业 | 某工作负责人周期内**连续在岗作业天数 ≥ 阈值**（config「长期作业连续天数阈值」，默认 5） | 工作负责人 | 每人一封 |

- 周期 = 报告日所在 ISO 周（周一至周日）；文号 `2026年第{ISO周}号`。
- 满载/重载函单位短语按模板区分工区（满载）与中心（重载）两种编辑口径，统一替换为 `国网青岛供电公司{单位}`；长期作业函主题句替换为 `国网青岛供电公司{单位}工作负责人{真名}连续工作超{N}天（{lo}至{hi}）`。
- 作业清单附表 10 列行 = 命中单位/负责人周期内各计划；外包两列（外包施工单位/外包人数）填「—」（外包专项暂不开展）；**工作负责人输出真名（不脱敏）**；行数超 `函件作业清单行数上限`（默认 300）仅列示前 N 项并末行标注「其余略」。
- 无命中单位/负责人时 letters 为空数组（ok JSON，退出码 0），下游自行提示。
